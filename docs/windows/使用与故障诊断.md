# PotatoFlow Windows 使用与故障诊断

## 数据位置

安装版把录播与导出放在资源管理器容易找到的“文档”目录：

- `文档\PotatoFlow\recordings`
- `文档\PotatoFlow\exports`

配置、数据库、Cookie、日志与缓存位于 `%LOCALAPPDATA%\PotatoFlow`。便携版则分别使用程序旁的 `data`、`recordings` 与 `exports`，移动整个目录即可迁移。

## 首次启动

首次打开依次确认数据位置、组件、录制策略、编码器和可选服务。B站账号、AI 和通知均可跳过。组件缺失时先打开“诊断与日志”，不要从网络单独替换 `biliup.exe`；录制核心与 PotatoFlow 版本锁定。

## 编码建议

- AMD Radeon 780M：`h264_amf / balanced / CQP 20`
- CPU 保底：`libx264 / medium / CRF 20`

烧录保留源分辨率、帧率和宽高比，支持 2160p。硬件编码失败只回退当前任务，不改变全局配置。烧录文件完成时会验证时长、视频流、音频流、分辨率与文件大小，验证通过前不清理原视频。

## 常见问题

“录制引擎尚未构建”：安装包不完整。诊断页应同时显示 `biliup.exe`、`ffmpeg.exe` 与 `ffprobe.exe`，并提供 SHA-256。

文件出现在临时目录：当前版本禁止把盘符 `C:` 清洗为 `C_`。若仍发生，请停止录制并导出脱敏诊断信息，勿手动移动正在写入的 `.part`。

停止录制：应用先请求录制核心完成当前文件和 XML 收尾，超时才终止整个 Windows Job Object。不要直接在任务管理器结束单个子进程。

卸载：默认保留全部用户数据。交互卸载可分别选择清理内部数据和录播/导出；后者会显示真实路径并再次确认。

## 诊断信息安全

诊断包不得包含 Cookie、API 密钥、Telegram Token、直播流签名或请求认证头。对外提交前仍应检查文件清单。
