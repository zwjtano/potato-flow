# v1.6.48

- 重做长录播 AI 标题逻辑：标题通常保留 18–42 字，最多 48 字，超长时要求模型重写，不再直接截断半句话；一小时录播按真实时间跨度校验主线或双看点，拒绝只覆盖末段小片段的伪主线。
- 标题、简介与封面统一使用已核验 XML、弹幕时间线和直播数据；明确人物、共同游玩/对战/观战关系、事件原因与结果时才写入，缺少证据的 5W1H 信息不再补猜。
- Dota 2 GSI 支持一段录播内多局英雄切换，按事件时间匹配主播、英雄、装备与明确结束边界；只确认对局结束但没有胜负证据时，不生成“本局结束/进入下一局”等低信息内容。
- 修复已发布稿件重新生成时丢失多局 GSI 的问题；标题、简介与 16:9/4:3 封面重做会继续保留对应局英雄和装备，封面按标题第一核心事件选择该局数据。
- 修复同时重生成标题和简介时标题失败却静默沿用旧题的问题；现在先生成并核验新简介，再独立重拟标题，分段 GSI 可直接证明主播与各局英雄关系，失败时不会继续发布或生图。
- Dota 2 封面在已有官方装备参考时必须清楚表现至少一件与核心事件相关的装备；图像模型阶段禁止仿画图标并为右下角留出安全区，成图后再用最多两枚 Valve 官方装备图标生成小型装备标识，避免装备藏进服装细节或混入其他游戏素材；缓存路径同时改为 Windows/Linux 通用的配置目录相对路径。
- GSI 封面提示词把最多六格主装备、中立物品和神杖/魔晶升级状态分开陈述，不再把中立物品列成相互矛盾的“第七件主装备”。
- 封面文案改为独立短文案，优先 8–18 字、最多 24 字；长标题不再整句塞入画面，16:9 与 4:3 分别构图并保留安全边距。
- 负面、未经证实且可能损害现实人物名誉的传言从标题、简介和封面中直接删除；中性消息使用“观众讨论”，明显玩笑使用“直播间调侃”，不再用“弹幕称”包装负面传言。
- 仅由弹幕支持的现实人身伤害说法（如受伤、出血、被打哭）也按高风险负面传言处理，不进入标题、简介或封面。
- 标题减少机械使用“弹幕/观众/直播间”，禁止“被指、被曝、据称、引发热议、出装引争议”等模糊或营销式归因；主播确实参与所选游戏事件时，强制自然交代人物与对应 GSI 英雄，观战时不误写为主播操刀。
- GSI 已确认主播操作时，标题禁止退化成“观众讨论/弹幕认为”开头，也不再用“结束后转入下一局/进入某英雄对局”等无信息过场串联多局看点。
- 设置页新增全局 AI 标题、简介和封面生图提示词；生效顺序为直播间单独设置、全局设置、系统内置，事实校验、人物身份、长度与素材安全约束始终不可覆盖。
- 已发布稿件编辑支持安全清空字段、重新生成标题/简介/双画幅封面并更新 B 站；合集写入改为幂等，已在目标合集的稿件不会重复添加。
- 修复任务列表只读取最近固定数量任务导致旧任务无法定位、失败任务自动重试和文件占用扫描漏查的问题；暂停/删除任务增强 Linux、macOS 与 Windows 的进程识别和子进程清理。
- Windows 桌面版为 FFmpeg、ffprobe、yt-dlp、biliup、PowerShell、GPU/CPU 探测等短时进程统一隐藏控制台弹窗，并修复卸载脚本路径转义；桥接任务库、录制任务库和任务租约库在事务结束后立即关闭 SQLite 文件句柄，避免任务结束后数据库仍被占用。
- Windows 非 UTF-8 控制台无法显示中文日志时改为安全转义输出，不再因 `UnicodeEncodeError` 中断合集、简介评论或其他投稿流程。
- GitHub Actions 新增 Windows 全量测试；发布 GitHub Release 时自动构建并上传 Windows x64 安装包、便携包及 SHA-256 校验文件，发布前完成服务模式、桌面资源和静默安装/卸载验证。

验证：本地完整测试共 926 项通过（根测试 610 项、应用测试 316 项），并使用 141 服务器真实一小时 XML/GSI 数据验证多局英雄、装备、人物主语和封面短文案链路。
