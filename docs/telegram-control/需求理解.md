## 2026-08-11 13:40

## 需求概述

基于 PotatoFlow v1.6.79 增强 Telegram 远程控制。当前版本已经支持直播间管理、录制启停、任务状态与进度、任务暂停/重试/删除、录播文件、录制引擎和磁盘状态，因此本次增强应聚焦交互效率或新增业务能力，避免重复已有命令。

## 当前能力

- `/rooms`、`/add`、`/start`、`/stop`、`/delete`
- `/tasks`、`/task`、`/retry`、`/pause`、`/delete_task`
- `/files`、`/engine`、`/status`、`/disk`
- Chat ID 与管理员 User ID 双白名单
- 删除直播间、删除任务和停止引擎二次确认

## 已确认范围

- [x] 首页控制台：引擎、直播间、进行中任务、异常任务和磁盘概览。
- [x] 直播间管理：按钮查看、启动、停止和二次确认删除。
- [x] 进行中与异常任务：独立筛选、阶段进度、上传进度和刷新。
- [x] 任务详情：流水线状态、错误、上传速度、ETA 与可用操作。
- [x] 录制引擎与系统状态：启动、二次确认停止和磁盘空间。
- [x] 通知与危险操作确认：显示通知配置和安全边界。
- [x] AI 编辑：查看 AI 元数据，二次确认后异步重新生成标题、简介、标签或封面。

### 通用要求

- [ ] 所有按钮操作继续执行 Chat ID 与管理员 User ID 双重鉴权。
- [ ] 删除、停引擎等高风险操作继续要求限时二次确认。
- [ ] 网络失败只反馈简洁错误，不泄露 Bot Token、Steam Key、文件绝对路径或上游响应正文。
- [x] 长列表首屏限制为 8 条，避免超过 Telegram 4096 字消息限制或按钮数量限制。

## 非功能需求

- 安全：保持现有白名单和确认机制；回调数据不可直接承载密钥或自由路径。
- 可用性：按钮回调应在 Telegram 时限内应答，耗时查询需要先确认收到。
- 兼容性：原命令全部保留，现有用户无需改变使用习惯。
- Windows：打包后不弹出控制台窗口，不增加新的系统依赖。

## 边界与约束

- Telegram Bot API 继续使用现有长轮询，不改为公网 Webhook。
- 不允许通过 Telegram 执行任意 Shell、任意文件删除或读取敏感配置。
- AI 重生成属于耗时操作，必须先应答回调并在后台执行，完成后主动发送结果。

## 验收标准

- 未授权用户无法通过命令或按钮触发任何状态变更。
- 原有 Telegram 命令回归测试全部通过。
- 新增能力在网络失败、空列表、过期按钮和重复点击时有明确反馈。
- Windows GitHub runner 全量测试与打包验证通过。
